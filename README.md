# QQ导出助手

把本机 QQ（NT 版，9.9.25 / 9.9.36）里的聊天记录导出成 **7 种格式**：
`.txt` / `.html` / `.json` / `.pdf` / `.markdown` / `.csv` / `.excel`

程序为单文件自包含 EXE（`dist\QQ导出助手.exe`）：内嵌 Python 3.12 运行时 + 全部依赖 + C# 自解压启动器，
双击即用，无需安装 Python、无需联网、不会修改 QQ 程序本身。

---

## 一、快速开始

1. 双击 `QQ导出助手.exe`
   - 首次运行会弹一个**「正在准备」小窗**（解包 60 MB 需要一两秒），界面就绪后自动消失。
   - 首次运行会自解压到**运行目录**下的 `app-<hash>\`（约 60 MB / 750 个文件）。
     解包目录里会写一个 `.payload.ok` 标记，**之后每次启动都直接复用、不再重复解包**
     （实测第二次启动 0 秒就绪）。
   - 界面是**程序自己的窗口**（WinForms + WebView2 内嵌浏览器），**不再弹出 Edge / Chrome**；
     看起来就是一个普通桌面程序，没有地址栏、没有标签页。
     > 机器上没装 WebView2 Runtime（Windows 11 自带，Windows 10 需单独装）时，
     > 会自动退回「用默认浏览器打开界面」。
   - **运行目录会自动回退**：默认 `%LOCALAPPDATA%\QQExportHelper`；如果那里不可写
     （被安全软件 / 受限环境拦下时会报 `UnauthorizedAccessException`），
     程序依次尝试 `%TEMP%\QQExportHelper` → **EXE 同目录的 `runtime\`**，用第一个能写的。
     实际用了哪个写在 `launcher.log` 里（运行目录和 EXE 同级各放一份）。
   - 同理，若**系统临时目录**不可写，子进程的 `TEMP/TMP/TMPDIR` 会改指到运行目录下的 `tmp\`
     —— SQLite 做 `ORDER BY` 时要写临时文件，没有可写临时目录会直接报
     `unable to open database file`。
2. 点击顶部 **「扫描 QQ」** → 程序自动定位 QQ 安装目录、版本、`nt_msg.db`，并列出**本机所有 QQ 账号**。
3. 在顶部**账号选择器**里选账号（状态徽章：`已就绪` / `需要口令` / `口令过期`）。
   - 换了 QQ 号之后，旧口令对新库无效 —— 点顶部橙金色的 **「🔑 获取密钥」**（或页面中央横幅上的 **「识别密钥」**），
     程序会针对当前账号重新抓一次；
   - **主界面已经没有手动输入框**：只要检测到「QQ 正在运行 + 这个账号还没有密钥」，
     就会自动弹出一次说明窗（三步：自动退出 QQ → 重新登录并截获密钥 → 自动恢复 QQ），
     同时页面中央出现橙色横幅、顶栏按钮开始呼吸高亮；
   - 真要手动填，从标题栏 **「?」→ 使用帮助 → 高级 → 「手动填写数据库密钥…」** 进去。
4. 点击 **「加载聊天记录」** → 左侧出现会话列表，点击会话即可在右侧浏览消息。
   > 第一次加载要解密整个 3.1 GB 的 `nt_msg.db` 并重建群消息表，实测约 **110 秒**；
   > 期间会在**运行目录**的 `plain\` 下生成约 **3.0 GB 明文库 + 1.8 GB 群表恢复库**
   > （合计约 7.8 GB），下次打开直接复用、不再重算。
   > **界面中央会浮出一张进度卡片**（当前步骤、百分比、已用时），可以点「最小化」收成右下角的小胶囊，
   > 窗口内还有一条细进度条；进度文字取不到百分比时会走不定进度动画。
5. 右下角选择 **导出格式** 与 **导出范围**，确认目录（默认 `D:\QQ导出`），点 **「开始导出」**。

### 不知道下一步点哪儿？看顶部那一行提示

界面顶部常驻一条 **「下一步」提示条**，它会把该做的事写成一句话，并**直接把该点的按钮圈出来**：

| 提示条说什么 | 它会高亮哪个控件 |
| --- | --- |
| 还没找到本机 QQ → 「请先安装并登录 QQ，然后点「扫描 QQ」」 | 顶栏 **扫描 QQ** |
| 没找到 QQ 数据目录（启动时已在后台自动全盘扫） | 顶栏 **扫描 QQ** + 左侧 **「找不到？点这里」** 变橙闪动 |
| 账号还没选 | 左侧 **账号下拉框** |
| 账号还没有密钥 | 顶栏 **🔑 获取密钥**（金色呼吸） |
| 密钥已就绪、还没读库 | 顶栏 **加载聊天记录** |
| 会话已加载、还没导出 | 顶栏 **导出** |
| 正在跑任务（扫描 / 抓密钥 / 读库 / 导出 / 全盘扫描） | 提示条变橙色，显示「进行中」和当前步骤文字 |

高亮的方式有三种，同时生效：**蓝色/金色呼吸光圈**、**按钮正下方一个上下跳动的小箭头**、
以及提示条里右端的 **「去操作」** 按钮（点它等于点那个按钮）。

不想看这条提示就点它右端的 **「×」**：同一步不再出现；等下一步变了它自己会回来。

### 首次运行时 Windows 提示「已保护你的电脑」怎么办

双击后如果出现蓝底白字的 **「Windows 已保护你的电脑 / Microsoft Defender SmartScreen 阻止了无法识别的应用启动」**，
应用名是 `QQ导出助手.exe` 或 `QQ导出助手-安装程序.exe`、发布者是 **「发布者未知」**，这是**正常现象**，不是病毒：

> 本程序没有购买代码签名证书，Windows 无法验证「是谁做的」，再加上它是新文件、还没有下载信誉，
> SmartScreen 就会拦一下。任何**未签名 + 新发布**的 exe 都会这样，跟程序本身做了什么无关。

三种处理方式（任选一种）：

1. **当场放行**：点弹窗里的 **「仍要运行」**（有些系统上要先点 **「更多信息」**，才会出现「仍要运行」）。
2. **提前解锁**：右键 exe → **属性** → 在「常规」页最下面勾选 **「解除锁定」** → 确定，之后再双击就不再提示。
3. **命令行解锁**（适合批量分发）：

   ```powershell
   Unblock-File -Path "D:\路径\QQ导出助手-安装程序.exe"
   ```

如果希望彻底不出现这个提示，需要给程序买一张 **代码签名证书**（OV 证书约 1000~3000 元/年，需要按年续费并积累信誉；
EV 证书价格更高但**立刻就有信誉**），然后用 `signtool` 签名即可。个人自用/小范围分发，用上面的「仍要运行」就够了。

> 从**别人那里拷来**的 exe（QQ / 微信 / U 盘 / 网盘下载）更容易触发这个提示，因为文件上带了「来自网络」的标记。
> 自己在本机构建出来的 exe 一般不会提示。



### 安装 / 卸载（可选）

绿色单文件直接双击就能用；想要桌面快捷方式、开始菜单项和「卸载程序」条目，可以走安装流程。

**推荐：双击 `QQ导出助手-安装程序.exe`** —— 安装包和绿色单文件是**同一个二进制**，只是文件名带「安装程序」，
所以双击它会直接弹出图形化安装向导：

1. 欢迎页 → 「下一步」
2. **选择安装位置**：可以直接改路径，也可以点「浏览…」挑文件夹（默认 `%LOCALAPPDATA%\Programs\QQ导出助手`）
3. 进度页 → 完成页（可以勾选「立即运行 QQ导出助手」）

安装完成后，桌面和「开始菜单」里都会有快捷方式，`设置 → 应用` 里也能看到并卸载。

也可以命令行调用：

```powershell
QQ导出助手-安装程序.exe                                    # 图形安装向导（推荐）
QQ导出助手.exe --install                                   # 同上，也弹向导
QQ导出助手.exe --install --install-dir D:\Tools\QQ导出助手 --no-launch   # 静默安装
QQ导出助手.exe --uninstall                                 # 卸载（删快捷方式 + 卸载项 + 安装目录）
```

> 安装包识别规则：文件名里含「安装」/「setup」/「install」就进安装向导；装好之后的
> `QQ导出助手.exe` 不含这些词，所以双击它是**启动程序**，不会又弹一遍安装向导。

安装后的目录结构是 `<安装目录>\QQ导出助手.exe` + `<安装目录>\runtime\app-<hash>\`（运行时）。
安装会写 `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\QQ导出助手` 卸载信息。

**卸载的安全护栏**（2026-10-22 加固）：

- 安装时会在安装目录里写一个 `.qqexport-install` 标记文件；卸载时**只有看到这个标记**，才会删除整个安装目录。
- 如果只是把绿色单文件放在某个文件夹里直接运行（没有装过），`--uninstall` **只删除它自己的 `QQ导出助手.exe` 和 `runtime\` 目录**，
  该文件夹里的其它文件一律不动 —— 不会出现「卸载把整个下载文件夹清空」这种事。
- 安装时如果选的目录本身是「桌面 / 下载 / 文档 / 用户主目录 / 盘符根」这类常见文件夹，程序会自动在它下面再套一层
  `QQ导出助手` 子目录，避免把用户文件夹本身当成安装目录。
- 卸载时的实际删除由**一个临时副本**（`%TEMP%\qqexport-cleanup-*.exe`）在进程退出后完成，
  用 .NET 文件 API 而不是 `cmd /c del`，因此中文路径、带空格路径都不会出问题；删完它会自己清掉。

**单实例与残留锁**（2026-10-22 加固）：

- 程序同时只允许开一个窗口（命名互斥体 `Local\QQExportHelper.SingleInstance`）。
- 启动时会把当前进程号写进 `<运行目录>\instance.lock`。如果发现互斥体已被占用，
  会先检查 `instance.lock` 里的进程是否还活着：**进程已经不在（上次崩溃 / 被强制结束）就当作残留锁，直接继续启动**，
  不会出现「明明没开却一直提示已经在运行」的情况。



### 换了一台电脑，界面显示「未找到账号 / 没有找到 QQ 消息库」

程序默认去这几个地方找 QQ 的数据目录（`Tencent Files`）：

1. **注册表里「文档」的真实位置**（很多人把「文档」从 C 盘挪到了 D 盘，这一条就是为它准备的）
   —— `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\User Shell Folders`
2. `%USERPROFILE%\Documents\Tencent Files`、`%USERPROFILE%\OneDrive\Documents\Tencent Files`
3. `C:\Users\<其它用户>\Documents\Tencent Files`（换过 Windows 账户的情况）
4. 每个固定盘根目录下的 `Tencent Files` / `TencentFiles` / `Documents\Tencent Files` / `QQ\Tencent Files`
5. 你之前手动指定过的目录（记在 `<运行目录>\roots.json`，只记目录、不记聊天内容）

全都找不到时，**程序会在启动时自动把所有固定盘扫一遍**（后台跑，界面照常可用，最多约 2 分钟），
一发现 `Tencent Files` 就记下来、账号立刻出现在列表里 —— 你不需要点任何按钮。

自动扫描也找不到时，账号面板下面会亮起一个橙色折叠入口 **「找不到？点这里」**，里面有：

| 按钮 | 作用 | 什么时候用 |
| --- | --- | --- |
| **重新扫描** | 再扫一遍所有固定盘（跳过 `Windows`/`Program Files`/`AppData` 等目录） | QQ 刚登录过、或刚把数据目录换到别的盘 |
| **指定目录…** | 自己粘贴 / 输入 `Tencent Files` 的完整路径 | 知道 QQ 装在哪、放在移动硬盘上的情况 |
| **诊断** | 生成一份纯文本报告（注册表文档路径、扫过哪些目录、每个账号的库文件与大小、QQ 进程），可一键复制 | 前两个都不行时，把报告发给开发者 |

扫描到的目录会写进 `<运行目录>\roots.json`，**下次启动直接可用**，不用再扫一遍。

> 只想快点拿到结果的话：在资源管理器里搜 `nt_msg.db`，找到后把它往上四级目录
> （`<账号>\nt_qq\nt_db\nt_msg.db` → `Tencent Files`）用「指定目录…」填进去即可。

> 想关掉自动扫描（比如磁盘慢、不想每次都扫）：设环境变量 `QQEXPORT_NO_AUTOSCAN=1`。


### 群消息表损坏与自动恢复（读库时的自动修复）

QQ 的 `nt_msg.db` 解密后是一份标准 SQLite 库，但 **群消息表 `group_msg_table` 的表 b-tree
指针链是坏的** —— 对它做整表扫描会直接报：

```
sqlite3.DatabaseError: database disk image is malformed
```

有意思的是它的**覆盖索引是好的**，所以 `SELECT count(*) FROM group_msg_table` 仍然能给出正确的
**2,882,289** 行 —— 数据其实还在，只是索引之外的访问路径断了。

程序遇到这种情况**不会报错退出**，而是自动走一条「旁路恢复」流程（实现见 `src/qqexport/recover.py`）：

1. 走**好的覆盖索引**取出该表的全部 rowid；
2. 顺序扫描明文库的所有 `0x0D`（表叶子页），解析出 cell，用 rowid 集合筛出属于该表的记录；
3. 按 rowid 升序回读原始记录，写进一份**结构正常的新库**（`*.group.db`，表名与列名都和原表一致）；
4. 把新库 `ATTACH` 进当前连接，此后**群表查询一律走它**（`GROUP BY` / `ORDER BY` /
   `WHERE 40030 = ?` 都能照常工作）。

实测（3.1 GB 明文库，2026-10-21 用打包后的 EXE 跑真实库）：**2,882,289 行全部恢复出来**，
耗时约 **102 秒**。
（更早一版在探针库的明文副本上跑出过 2,878,533 行、差 3,756 行，那是当时那份副本的状态；
打包产物对真实库实测是全量恢复。）
这段时间界面会显示进度（扫到百分之几、已定位多少行），属于正常现象，请耐心等待。

恢复库会缓存在明文库旁边（`*.group.db`），**下次打开直接复用**，不会重跑一遍。

> 只有真的需要恢复时才会走这一步；库结构正常的话完全不会触发。
> 万一恢复失败，程序会退回「直接读原库」并在界面上给出提示，不会崩溃 —— 但那时群消息可能读不全。

## 二、密钥（SQLCipher 口令）怎么来

`nt_msg.db` 是 SQLCipher 加密库，口令是 16 字节 ASCII，**每个 QQ 账号固定**，无法从文件离线推导。

### 方式 A：自动获取（推荐，程序内置）

点顶部橙金色的 **「🔑 获取密钥」**（或页面中央橙色横幅上的 **「识别密钥」**）。程序会：

0. **先自动结束正在运行的 QQ**（抓口令要求 QQ 重新打开消息库），抓完再把 QQ 重新启动起来；
   结束进程先走 `taskkill`，被安全软件拦下时再逐个 `TerminateProcess` 兜底；
   如果实在关不掉，会明确提示「请先手动完全退出 QQ（任务栏托盘里的图标也要退出）」，而不是闷着失败。
1. 静态解析 `wrapper.node`，自动定位 `nt_sqlite3_key_v2` 的调用函数 RVA
   （9.9.25 实测 `0x21A7D10`，9.9.36 实测 `0x21EBE20` —— 定位靠**特征串**而不是写死的地址，
   所以 QQ 升级后一般还能用）；
2. 以调试方式启动 QQ，监听 `wrapper.node` 加载事件；
3. 在该函数下断点，命中后把 R8 / R9 / RBX 等寄存器指向的内存全部当作候选口令；
4. 每个候选都用**纯 Python 的 SQLCipher 校验器**去解真实的 `nt_msg.db`（PBKDF2-HMAC-SHA512 / 4000 次 / HMAC-SHA1 / AES-256-CBC / 页 4096），
   只有真的能解出 `sqlite_master` 才算命中；
5. QQ 自带的反调试保护（`call [api] / test eax,eax / je / int3 / ud2`）在命中时被"模拟成无调试器"——
   把 EAX 改回干净机器上的返回值、RIP 退回 `test` 指令，**不改 QQ 的任何代码**，保护器的自校验照样通过。

> **换 QQ 号怎么办**：口令是**跟着账号走的**，换了号旧口令对新库无效。
> 在顶部的账号选择器里选中新账号 → 点「🔑 获取密钥」，程序会针对**那个账号的库**重新抓一次口令，
> 并把结果按「数据库完整路径」记进运行目录的 `keys.json`（以后这台机器上这个号直接复用）。
> 账号列表右侧的徽章会显示状态：`已就绪` / `需要口令` / `口令过期`（库比口令新，可能要重抓）。
>
> **界面的自动引导**：只要检测到「QQ 正在运行 + 当前账号没有密钥」，程序会
> ① 在页面中央弹出橙色横幅、② 让顶栏的「🔑 获取密钥」按钮呼吸高亮、③ **自动弹一次**三步说明窗
> （自动退出 QQ → 重新登录并截获密钥 → 自动恢复 QQ）。点「识别密钥」才开始，不会偷偷动你的 QQ。
> 说明窗只自动弹一次，关掉后再点按钮或横幅才会重新出现。

> **使用前请先完全退出 QQ**（任务栏托盘也要退出）。QQ 有单实例互斥，已在运行时再拉起会直接转发退出，
> 断点自然命不中。程序已经会自动帮你结束 QQ；如果你自己先跑起来了，抓取仍可能失败。
> 调试版 QQ 起来后如果弹出登录窗口，请在窗口里完成登录——数据库正是在登录那一刻才被打开。

> 调试版 QQ 起来后，**请在那个 QQ 窗口里完成登录**（程序在等口令，最长 15 分钟）。

> ⚠️ **程序必须放在「普通目录」里运行**（安装程序默认装到
> `%LOCALAPPDATA%\Programs\QQ导出助手`，就是这个意思）。
> 如果放在某些带有子进程限制的沙箱或安全软件环境里，程序本身能跑、界面也能开，但**自动抓口令会失败**——被调试的 QQ 会以 `0x80000003` / `0xC0000005` / `0xC000001D` 退出。
> 这种情况界面会给出提示，也可以直接在「手动填写」里输入口令。

### 方式 B：手动填写（藏在帮助里）

如果你用别的方式拿到了口令（例如官方 `windows_ntqq_get_key.ps1`、IDA 断点、frida hook），
从标题栏 **「?」→ 使用帮助 → 高级 → 「手动填写数据库密钥…」** 打开输入框，粘贴 16 位字符串即可。
口令校验方式与自动获取完全一致，填错会立刻报错而不是解出乱码。

> 主界面上**故意不放**手动输入框：绝大多数人的口令都能自动抓到，摆一个输入框只会让人困惑
> （而且很容易把 `login.db` 的 20 字节常量当成口令填进去）。

> 附带说明：QQ 客户端里硬编码了一个 20 字节常量 `BD156D6710D54D8782F4`，那是 **login.db**（登录态库）的固定密钥，
> **不是** `nt_msg.db` 的口令，填进去会失败。

## 三、导出产物

| 格式 | 产物 |
|---|---|
| `.txt` | 每会话一个 `.txt` + `index.txt` 目录页 |
| `.html` | 每会话一个 `.html`（自带样式，可直接浏览器打开）+ `index.html` |
| `.markdown` | 每会话一个 `.md` + `index.md` |
| `.csv` | 每会话一个 `.csv`（带 BOM，Excel 直接打开不乱码）+ `index.csv` |
| `.json` | 单一 `qq_export.json`（含全部会话与消息，便于二次处理） |
| `.pdf` | `qq_export.pdf` 合订本 + 每会话单独 `.pdf` + `index.txt` |
| `.excel` | `qq_export.xlsx` 合订本（每会话一个 sheet，超行数自动分片）+ 每会话独立 `.xlsx` + `index.xlsx` |

同名的会话不会互相覆盖（**文件名**自动加 `_2` / `_3` 后缀）。缺 reportlab / openpyxl 时只禁用对应格式，其余照常导出。

### 全量导出（真实库规模）

真实库实测规模：**约 290 万条消息 / 454 个会话**，其中最大的一个群有 **1,310,064 条**消息。

导出是**流式**的：程序先只读会话元数据（会话名、消息条数、时间范围），再**逐个会话**地把消息
读出来、写出去，写完一个就丢掉一个。所以**内存占用只与「最大的那个会话」有关**，而不是整库 ——
不会因为消息多而把内存撑爆。

Excel 单个 sheet 的行数上限是 1,048,576 行，所以**超过这个行数的会话会自动分片**成多个
sheet（`会话名` / `会话名 (2)` / …），既不报错也不丢数据。实测最大的群「电脑互助群」
（131 万条）就拆成了 `电脑互助群` / `电脑互助群 (2)` 两张；每个会话的独立 `.xlsx` 同样拆 2 张。

> 两种后缀不是一回事，别混淆：**同名会话**（两个会话撞名）用 `_2` / `_3`；
> **同一个会话超行数分片**用 ` (2)` / ` (3)`。

**全量实测**（真实库 454 个会话 / 2,880,272 条消息，单机 32 核，**七种格式全部 `ok=True`、零错误**）：

| 格式 | 用时 | 产出体积 | 产物个数 |
|---|---|---|---|
| `.txt` | 1 分 45 秒 | 229 MB | 455 |
| `.markdown` | 1 分 43 秒 | 235 MB | 455 |
| `.csv` | 1 分 47 秒 | 447 MB | 455 |
| `.html` | 2 分 01 秒 | 690 MB | 455 |
| `.json` | 2 分 28 秒 | 1.69 GB | 1 |
| `.pdf` | 2 分 55 秒 | 408 MB | 456 |
| `.excel` | 9 分 15 秒 | 431 MB | 456 |

七种全导一遍约 **22 分钟**、产物合计约 **4.1 GB**。
全程**内存峰值稳定在 1.5 GB 左右**，且不随格式、总量变化 —— 唯一的内存大头是
「最大的那个会话」要一次性读进内存（131 万条消息 ≈ 1.2 GB）。
`.pdf` 合订本实测约 12.8 万页。

> 小提示：`.json` 会把每条消息的附件元数据都写进去，所以体积是 `.txt` 的 7 倍多；
> 只想要正文的话用 `.txt` 或 `.csv` 更划算。

### 群名 / 昵称从哪来

QQ 的**消息表里没有群名字段** —— `group_msg_table` 只存「发送者的群名片」（`40090`）。
群名在**最近联系人表** `recent_contact_v3_table` 的 **`40094`** 列里：

| 会话类型 | `40094` 列 | `40093` 列 |
|---|---|---|
| 群聊 | **群名**（如「哈工大铁路协会」「电脑互助群」） | 我本人在该群的昵称 |
| 单聊 | 对方的昵称 | 我给对方设的**备注名** |

程序读会话列表时会把 `40094` 取出来当会话名。单聊优先用 `40094`（对方昵称），取不到时回退到
`40093`（备注名）。群聊**只用** `40094` —— 群行里的 `40093` 是「我自己在该群的昵称」，
拿它当群名会张冠李戴。

**覆盖率**：实测 94 个群会话里 **64 个能拿到群名**（例如「哈工大铁路协会」「电脑互助群」）；
剩下 30 个群，**QQ 客户端本地就没缓存群名**，程序会**如实退化成群号字符串**。
这是数据本身的限制，不是程序的 bug —— 取不到的名字，程序不会猜测、也不会编造。

## 六、已知限制

- 真实 `nt_msg.db` 约 3.1 GB，首次解密要几分钟，界面会显示进度。
- **全量导出并不轻量**：真实库约 288 万条消息，七种格式全导一遍约 **22 分钟**、
  产物合计约 **4.1 GB**（逐格式明细见「三、导出产物」）。内存峰值稳定在 1.5 GB 左右，
  但目标盘要先留出 **4 GB 以上**空间。
- QQ 客户端自带的消息备份目录（`nt_data\msgbackup\temp`）里正文是服务端密钥加密的，
  离线不可解，只能读到时间/类型等元数据 —— 真正的聊天记录仍来自 `nt_msg.db`。
- **群名大部分拿得到，但不是全部**：消息表里确实没有群名字段，群名取自最近联系人表
  `recent_contact_v3_table` 的 `40094` 列。实测 94 个群会话里 64 个有群名；剩下 30 个群，
  QQ 客户端本地就没缓存群名，导出时会**如实退化成群号字符串** —— 这是数据本身的限制，
  不是程序的 bug。
- 群消息表的 b-tree 指针链本身是坏的，程序靠旁路恢复（扫叶页重建 `*.group.db`）才能读到群消息。
  打包产物对真实库实测 **2,882,289 行全部恢复**（更早一版在探针副本库上跑出过 2,878,533 行、
  差 3,756 行，约 0.13%），首次恢复约需 100 秒；恢复库会被缓存复用，之后打开不再重复。
  万一恢复失败，程序会退回直接读原库并提示 —— 那时群消息可能读不全（但不会崩）。
- **解密缓存也要磁盘**：首次加载会在**运行目录**的 `plain\` 下生成
  约 **3.0 GB 明文库 + 1.8 GB 群表恢复库**（合计约 **7.8 GB**）。这是明文聊天记录，
  介意的话用完可以整个删掉（删了下次会重新生成，约 110 秒）。
- 语音等附件在 `nt_msg.db` 中只存类型与大小，媒体文件本体在 `nt_data\` 下，导出器会把可定位到的本地路径一并写入。

### 界面显示不出来时（白屏）

程序默认开的是**自己的窗口**（WinForms + WebView2），不走外部浏览器，所以一般不会遇到白屏。
如果机器上没装 **WebView2 Runtime**（Windows 11 自带；Windows 10 需要单独装，或者微软官方
「Evergreen Bootstrapper」），程序会自动退回「用系统默认浏览器打开界面」，这时可能遇到下面这些坑：

- 崩溃转储里写得很清楚：`SandboxLaunchFailure-ResultCode = SBOX_ERROR_CANNOT_CREATE_LOWBOX_TOKEN`，
  同时 `AppContainerRegisterSid failed … 0x80070005`（拒绝访问）——
  **Chromium 建不出渲染进程要用的低权限令牌，渲染进程一启动就崩**，于是只剩一个空窗口。
  受限令牌、杀软、企业策略都可能造成这个。
- 还有一个变种：老的 Edge「应用窗口」（`--app=`）会把窗口标题显示成地址而不是页面标题。

浏览器模式的应对是三级递进（`src/qqexport/app.py` 的 `_open_interface`）：

1. 正常开浏览器，**用界面 JS 主动回报（`POST /api/ui-alive`）当判据** ——
   只看首页有没有被下载是不够的（那种情况窗口照样是白的）；
2. 15 秒内没等到回报，就关掉窗口，**加 `--no-sandbox` 重开一次**（渲染进程不再需要低权限令牌）；
   这时 Edge 顶部会提示「不受支持的命令行标志：--no-sandbox」，属正常现象；
3. 还不行就改用系统默认浏览器；最后实在不行会弹窗给出可手动访问的地址
   （`http://127.0.0.1:<端口>`）。

只对自己的独立配置目录（`edge-profile`）打开本地页面，关掉浏览器沙箱的影响有限。

> 想强制用浏览器模式：`QQ导出助手.exe --ui browser`。
